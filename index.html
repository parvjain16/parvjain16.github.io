How is this site built?

A little look behind the scenes!

  1. The circular trailing cursor

    A circle follows the pointer with a slight delay, stretching as you move faster. It reverses the colors beneath it, appearing dark over light areas and light over dark areas so it stays visible across the page.

    The cursor is a 36-pixel HTML layer positioned above the page. Each animation frame interpolates its position toward the pointer, with timing adjusted for different screen refresh rates. Pointer speed and direction control stretching and rotation. CSS difference blending combines its white fill with the pixels underneath, inverting their colors so the cursor stays visible on both light and dark backgrounds.

  2. How the cursor wraps around links

    When you hover over GitHub, my email, or navigation links such as Projects, the site measures the item and reshapes the cursor to frame it. The shape follows your movement slightly, then returns to a circle when you move away.

    Hover detection identifies the link or button beneath the pointer and measures its position and dimensions. The cursor transitions to those dimensions, adding spacing and adjusting its corner radius for the target. A magnetic offset blends the target’s center with the pointer’s position, so the shape stays attached while responding to movement. Leaving the target releases that attachment and restores the circular shape.

  3. Liquid-metal “Parv Jain”

    My name is rendered with moving highlights and reflections that give the letters the appearance of polished metal. Your pointer changes those reflections, and clicking sends a ripple across the surface.

    Canvas2D first draws the lettering into an image. The site converts this into a distance field that records how far each pixel is from a letter’s edge. WebGL2 uses that information to calculate simulated surface angles, beveled edges and depth. Custom GPU shaders combine those angles with moving reflections and highlights to create the metal finish. Pointer movement and click waves alter the shading, giving the flat text the appearance of a liquid surface.

  4. The font throughout the site

    The site uses Product Sans, including the introduction and this panel. Regular and bold weights give the text a consistent look while distinguishing descriptions from headings. The font files are stored with the website.

    Product Sans is loaded from regular and bold font files stored with the site. Shared CSS applies the same font family across pages and this panel. The browser can display a system fallback while the files load, keeping text visible during loading. Once the font is ready, the liquid-metal renderer rebuilds its text image using the bold face so the canvas lettering matches the rest of the design.

  5. Node Network canvas

    The site draws moving points and connects nearby ones with lines. Your pointer pushes points aside and temporarily separates connections, while clicking sends a pulse through the network. The drawing updates continuously as the points move.

    Canvas2D draws a particle system whose nodes store their positions, movement and connections. A spatial grid groups nearby nodes, reducing the work needed to find neighbors. Connection limits keep the network readable, while spring forces and damping control how nodes move away from the pointer and settle back. Connections fade when disturbed and recover over time. Clicks add outward forces and animated pulses that travel through the network.

  6. Topographic Contours canvas

    The site calculates a shifting surface and draws contour lines along areas of equal height, much like a topographic map. Moving your pointer raises the surface nearby, and clicking sends a wave through the contours.

    The surface is represented by a grid of height values that changes over time. A marching-squares algorithm finds where each of 14 elevation levels crosses the grid cells, then Canvas2D draws the resulting contour lines. A fixed-step wave simulation updates neighboring cells to spread motion while damping gradually reduces it. Ambient movement, local pointer displacement and click-generated waves combine to shape the final surface.

  7. Persistent Plasma field

    This field builds on its previous frame, so colors continue flowing after your pointer moves away. Moving through it adds motion and color, while clicking changes the drawing color and creates a ripple. The trails gradually fade, and refreshing starts a new field.

    WebGL2 runs the simulation on the GPU using two textures that alternate between reading the previous state and writing the next. They hold movement and dye information. Each update transports dye through the velocity field, adds pointer forces, and applies diffusion and gradual decay. A separate rendering pass converts that state into color and lighting. Keeping the previous state creates lasting trails during the session; reloading the page resets the simulation.

  8. The horizontal WebGL photo gallery

    The gallery repeats the photos to create a continuous track in either direction. Scrolling and dragging build momentum, while gradual changes in speed make movement feel smooth. The photos bend slightly as they move, with your device’s graphics hardware drawing each frame.

    WebGL2 maps each photo onto a subdivided surface. GPU shaders move points on that surface according to scroll speed and pointer position, creating the bending and rotation, while a pixel mask rounds the corners. Repeated image instances wrap around the track to create continuous movement in either direction. A custom spring-and-momentum model smooths input independently of Lenis. Standard HTML images provide a fallback when WebGL is unavailable.

  9. Gallery detail mode: opening a photo

    Clicking or tapping a photo expands it into a larger view with its story. The site pauses the page behind the overlay and remembers your position. Closing the view returns you to the gallery so you can continue where you left off.

    The gallery identifies the selected photo and records its on-screen position and size. It then hides that WebGL image and animates a separate HTML image from the same position into the expanded view using CSS transforms. The page’s scroll position is saved, Lenis is paused, and keyboard focus stays inside the overlay. Closing coordinates the return animation with the WebGL image, restores focus without scrolling, and resumes the page from its saved position.

  10. Projects-only inertial motion

    Project images, text and buttons respond to scrolling with slightly different timing. Their movement gradually catches up with the page and settles when you stop. Buttons also shift gently toward your pointer, adding a sense of depth and responsiveness.

    A custom JavaScript controller converts scroll velocity into target offsets for project images, text and buttons. Each group uses a spring model with its own stiffness and damping, creating different amounts of lag and settling. CSS transforms apply the movement, with small rotation and scale changes on images. Separate springs handle magnetic button movement. Visibility tracking limits offscreen updates, and mobile and reduced-motion settings scale back or disable the effect.

  11. Smooth scrolling with Lenis

    Lenis is a scrolling library that turns mouse-wheel input into a gradual change in page position. Its code is stored with this website. Touch devices keep their native scrolling, and reduced-motion settings turn the smoothing off.

    Lenis converts mouse-wheel input into a target scroll position and interpolates the displayed position toward it. The library is stored locally and updated by the same animation loop that drives the site’s visual effects. Wheel sensitivity and interpolation control the feel of the movement. Touch scrolling stays native, overlays use their own scrolling, and reduced-motion preferences bypass the smoothing. The gallery’s horizontal momentum is handled separately.

  12. Dark mode

    The theme button switches between light and dark palettes. Text, backgrounds and interactive artwork update together, and your browser saves the choice for future visits.

    The toggle changes a theme class on the page, allowing CSS to switch the background, text and component colors together. The canvas controllers observe that change and update their rendering palettes. The preference is saved in the browser’s local storage and restored early during page loading to reduce flashes of the wrong theme. If storage is unavailable, theme switching still works for the current visit.
